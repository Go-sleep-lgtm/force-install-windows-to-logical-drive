# 强行将 Windows 装入物理逻辑分区（WinToGo + WIM 强制释放）

## 🎯 我想干的事
- **主系统**：Win10 装在物理硬盘的主分区上，当主力，用来写代码。
- **副系统**：Win7 装在同一块物理硬盘的另一个“逻辑分区”里，专门用来打游戏。

## 🕳️ 踩坑：安装器直接报错
一开始想常规操作，进 Windows 安装器，直接选那个逻辑分区。
结果安装器直接弹红字报错，根本不让选！
后来查了才知道，传统 BIOS/MBR 架构下，Windows 原生安装程序有死规矩：系统必须装在“主分区（Primary）”，逻辑分区直接给你锁死。

## 🧠 破局思路：先跑通，再搬家
既然 ISO 安装程序不让装，那就不在物理机上调 ISO 了。
思路转换：**先找个能装的地方，把系统彻底跑通，然后再把整个系统“搬”进逻辑分区。**
这就好比先在平地上把车造好、跑顺了，再把它开进指定的车位，而不是在车位里强行造车。

## 🛠️ 实操步骤（野路子版）
1. **WinToGo 跑通**：先用 WinToGo 工具，把 Win7 装到一个 16G 的 U 盘里。
2. **走完初始化**：在 U 盘里正常开机，走完所有 OOBE（初始设置），装好基础驱动，确认系统完全可用。
3. **进 PE 环境**：重启电脑，进入 PE 启动盘（我的 PE 底层是 Win11）。
4. **抓取 WIM**：用 Dism++，把 U 盘里那个已经跑通的系统，完整捕获成 WIM 镜像。
5. **强行释放**：用 Dism++，把抓好的 WIM 镜像，强行释放到物理硬盘的那个“逻辑分区”里。
6. **重启**：拔掉 U 盘，重启电脑。

## 🎉 结果
直接进了桌面！
软件、数据全都在，甚至没有碰到任何报错。
最离谱的是：`bcdboot`、`bootsect` 这些让人头秃的引导修复命令，我一条都没敲过。

## 🤔 为什么能成？（个人原理解析）
网上教程全是从 ISO 直接装，所以会卡在分区格式和引导重建上。
但我用的是**“捕获跑通系统的 WIM”**。
因为 WIM 镜像里已经包含了完整的引导文件结构（Bootmgr 等），Dism++ 在释放时，大概率是自动把引导写进了主系统（Win10）的 BCD 菜单里。
**核心避坑点**：源必须是“已经跑通、走完初始设置”的系统，绝对不能是干净的 ISO 镜像。就这一步，直接跳过了最麻烦的引导修复。

## 💻 我的硬件环境
- ThinkPad X230（三代 i5，老古董）
- 16G U 盘一个（用作 WinToGo）
- 8G 启动 U 盘一个（微PE）

---
如果你也卡在“逻辑分区无法装系统”或“装完死活进不去、无限蓝屏”的坑里，可以试试这种“先跑通，再搬过去”的降维打击法。有说错的地方，欢迎大佬指正。
